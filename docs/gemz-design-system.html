A refined pass on Gemz's existing design system

Every color, typeface and spacing value below already exists somewhere in theme.css or a template — nothing here is invented from scratch. What's changed is consolidation: one chip pattern instead of twenty near-duplicates, one brand hue instead of two that swap between themes, one type pairing instead of five loaded fonts. Toggle the theme picker on the left to check everything in both modes.

Color

Your teal is kept exactly — it already reads well for a marine/offshore client. The fix is structural: one brand hue across both themes, semantic colors given their own distinct hues, and neutrals warmed very slightly toward the brand instead of generic Bootstrap slate.

Found in the current CSS: light mode's brand is teal (#0D9488) but dark mode's brand is emerald (#059669) — a different hue, not just a different shade. On a white-label product where a client's brand color is the whole point, the brand shouldn't change identity when someone flips a display setting. Below, brand stays teal in both themes; only lightness shifts for contrast.

Every neutral above is derived with color-mix() from the brand hue at 3–14%, so cards and borders read as part of the same family as the brand color rather than a generic gray shipped with any template. When Hydrodive's teal is swapped for a future client's color, these neutrals shift with it automatically.

Typography

The app currently loads five font families (Google Sans, Noto Sans, Poppins, Karla, plus a cursive script for the logo) for what is fundamentally a two-role interface: headings and body text. This pairs down to two, both already in static/fonts/ — nothing new to license or host.

Display & numbers — Poppins
Escalations resolved on time
Section headings, KPI values, the wordmark
Body & UI — Noto Sans

Used for everything a person reads at length: ticket descriptions, table cells, form labels, comment threads. Noto Sans keeps its shape at small sizes and covers the full Latin range comfortably, which matters once other clients bring their own languages onto the platform.

Spacing, radius & elevation

Corner radii currently range from 0.375rem to 1rem seemingly at random between similar components (a modal and a form card, for instance, don't match). Three named radii and three shadow tokens replace the one-off values scattered through the stylesheet.

Buttons

Same five intents you already have (.btn-primary/outline/ghost/danger/success), tightened to one consistent height, padding and hover behavior. .btn-attachemnt (the typo) and its correctly-spelled but unstyled sibling .btn-attachment both go away — attachments use the ghost icon-button pattern instead.

Status & metadata

Tickets carry 13 status values. The current CSS gives each its own hand-picked color — .status-chip.pending_user, .pending_vendor, .pending_approval, .pending_manager_review and .pending_fulfillment are five separate rules that render identically (same amber). Below, one chip shape takes a data-tone and the label text — which already says "Pending Vendor" vs "Pending User" — carries the specific meaning. Five tones instead of thirteen rules.
